# Owmee Render Production Deploy

This repo includes a Render Blueprint at `render.yaml` for the backend API,
Temporal worker, managed Postgres, and Render Key Value.

## What Render Runs

- `owmee-api`: FastAPI Docker web service, health checked at `/health`.
- `owmee-worker`: Temporal worker Docker service.
- `owmee-postgres`: Managed PostgreSQL 16 database.
- `owmee-redis`: Render Key Value service used through `REDIS_URL`.

The API image runs `sh /app/start.sh`. The worker image runs
`sh /app/worker.sh`. Database migrations run through Render's
`preDeployCommand` before the API release starts.

## Required Production Secrets

Fill these in the Render Blueprint flow before the first deploy:

- `JWT_PRIVATE_KEY` and `JWT_PUBLIC_KEY`: escaped single-line PEM values.
- `R2_ENDPOINT`, `R2_ACCESS_KEY`, `R2_SECRET_KEY`, `R2_PUBLIC_URL`,
  `R2_PUBLIC_ENDPOINT`.
- `TEMPORAL_HOST`, `TEMPORAL_API_KEY`, and `TEMPORAL_NAMESPACE` if not `default`.
- `ALLOWED_ORIGINS`: production admin/app origins only, no localhost.
- `APP_BASE_URL`: final API URL, for example `https://api.owmee.in`.
- Gemini credentials if AI listing assist should work now.
- SMS, KYC, payment, Stream, FCM, and Sentry credentials as needed.

`SECRET_KEY` is generated by Render. Keep `autoDeployTrigger: off` until a
release checklist is green; deploy intentionally from known commits.

## JWT Key Generation

Generate keys locally and paste escaped values into Render:

```sh
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out /tmp/owmee-private.pem
openssl rsa -in /tmp/owmee-private.pem -pubout -out /tmp/owmee-public.pem
awk 'NF { gsub(/\r/, ""); printf "%s\\n", $0; }' /tmp/owmee-private.pem
awk 'NF { gsub(/\r/, ""); printf "%s\\n", $0; }' /tmp/owmee-public.pem
```

## Database Notes

Owmee uses PostGIS geography columns for listing location. The Alembic migration
environment creates `postgis` before running migrations, so a fresh Render
database can migrate from zero. If a database provider blocks extension creation,
enable PostGIS manually before deploy or switch to a PostGIS-capable managed
Postgres provider.

## Cloudflare R2

Create two buckets:

- `owmee-media`: listing photos and public media.
- `owmee-evidence`: private evidence and dispute material.

Use the S3 API endpoint for internal and presigned operations:

```txt
R2_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com
R2_PUBLIC_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com
```

Use the public bucket URL or custom domain for image display:

```txt
R2_PUBLIC_URL=https://media.owmee.in
```

If you start with Cloudflare's managed public bucket URL, use that as
`R2_PUBLIC_URL` and switch to the custom domain later.

## Mobile App

Render hosts the backend only. Before distributing Android builds, point the
mobile API config to the Render API domain, rebuild, and smoke test OTP, home
feed, search, listing detail, safe-buy CTA, make-offer CTA, sell flow, profile,
and notifications.

## Release Gate

Run this from `/Users/dev/owmee-prod` before pushing a release commit:

```sh
docker exec -w /app owmee_api pytest -q
docker exec -w /app owmee_api alembic current
docker exec -w /app owmee_api alembic heads
cd admin && npm run build
cd ../mobile && npm run tsc && npm run lint:design
cd android && ./gradlew assembleDebug
```

Then run the API smoke script against the target URL. Do not promote if OTP,
feed, listing detail, wishlist, offers, transactions, or safe-buy routes fail.
